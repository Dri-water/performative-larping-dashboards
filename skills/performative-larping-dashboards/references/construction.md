# Construction playbook: make the difficult parts repeatable

## Pass 1 — a shot, not a layout

First audit the real source and name the useful question and observed input → transformation → output. Read
[real work](real-work.md). Assign the dominant forms roles in that process;
the shot should depict an instrument performing work, not merely an impressive object.

Select a spatial metaphor and draw its largest masses first. Set the delivery
camera/aspect ratio immediately. Block one dominant form, a secondary system
crossing or interacting with it, distant context, and cropped foreground structure.
Light this without HUD text. Render a frame. Fix scale, depth, and silhouette now.

Common failure: a little object floats in a huge rectangle. Repair by changing
camera/composition and building the surrounding environment, not making its label
bigger. A strong hero may be 2D/2.5D; it still needs scale and authored complexity.

## Pass 2 — manufacture the object

Work down three scales rather than adding equally sized decorative objects:

- **Architecture:** containment volumes, ribs, layered terraces, shrouds, field
  sheets, suspended machines, or mountain-like data strata.
- **Assemblies:** hinges, rotors, actuator banks, manifolds, sensor arrays, shutters,
  channel bundles, extruded data plates. Make parts articulate around designed pivots.
- **Surface detail:** seams, grooves, fine ticks, fasteners, terminal blocks,
  engraving, cables, glyphs, ports, and emissive inserts.

For hard-surface procedural geometry, a useful starter is 8–24 major assemblies,
several distinct structural layers, and hundreds of instanced small parts. These
counts are a means to detail, not evidence of visual success. Vary modules with a
seeded function; break perfect repetition at higher scales. Use bevels or deliberate
edge highlights so facets have readable material response.

For finance, the equivalents can be irregular stacked price strata, extruded books,
contour ribbons, enormous curved tick tapes, and volume-like trade fields. Do not
force mechanical bolts onto an organic visual concept.

## Pass 3 — fields, optics, and instruments

Add translucent/particle fields that intersect the architecture and travel through
it. Use depth-tested rendering so trails disappear behind physical surfaces.
Create a few signature materials rather than a different effect per part.

Add a second instrument scale: one substantial wireframe diagram, spectrum,
cross-section, or contour plot, then smaller annotation fields. Tie some labels
to projected 3D positions; keep other instrument clusters intentionally screen-space.
Use collision-free lanes and leader lines instead of letting floating labels pile up.

Typography remains outside scene bloom. Decorative microtype may be dense and
cryptic; functional controls, exact values, source freshness and replay status remain readable.

## Pass 4 — direct the performance

Build motion around source events. Read choreography.md. Use independent visual phases
inside one timeline: counter-rotation, slow precession, streaming traces, scanning
cross-sections, load waves, mechanical opening, and a climactic transmission.

Map observed pending work → transformation → output → retained history. A material-colored
light change alone is too weak for the main event. Change geometry, topology,
depth, composition, or flow direction. A labeled recorded busy interval can demonstrate the design immediately.
Actual source silence must remain visible; do not fill it with invented work.

## Pass 5 — render / critique / repair

Capture a representative real busy interval and quiet/stale states at desktop
and portrait. Watch the actual event-driven sequence. List the three most consequential visual weaknesses.
Make targeted changes, then capture again. Do not spend the final pass only fixing
tests while accepting weak art direction.

| Observed result | Repair |
|---|---|
| Looks like a toy | Add intermediate assemblies, credible material scale, dark mass, and edge detail |
| Looks like a glowing logo | Introduce asymmetric depth, overlapping systems, camera obliqueness, and foreground context |
| Bright noisy soup | Keep detail; lower subordinate luminance, recover dark masses, localize bloom |
| Static despite many particles | Animate the actual architecture; author a clear transformation |
| Flat charts around a render | Turn selected data into spatial geometry, projections, ribbons, or sections |
| Portrait is a cramped thumbnail | Re-stage camera, assemblies, and labels; reduce peripheral text instead of shrinking the hero |
| Everything moves identically | Separate timescales, phase offsets, directions, and event envelopes |
| Pretty but seems to do nothing | Trace one input through decisions and visible outputs; drive motion and related views from those events |

Only after these passes should selectors, export buttons, loaders, and documentation
dominate the work. Test controls as they are added, but never confuse their completion
with the visual brief being fulfilled.
