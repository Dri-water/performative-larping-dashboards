# Performative Larping Dashboards

Make the system feel like a tiny civilization operating an unnecessarily powerful
machine. The deliverable must be beautifully excessive, coherent, and runnable.
Do not let a default component library decide the composition.

## Choose the production route

Read [the maintained toolkit](references/toolkit.md), then the relevant platform
recipe: [React](references/react.md), [HTML](references/html.md), or
[native / desktop](references/native.md). Read [production](references/production.md)
when using Blender, MCP tools, imported models, or video export.

Use the named default for that route. Inspect the user's existing project before
adding dependencies; retain established compatible tools. If the preferred tool is
missing, perform authorized project-local setup or explain the documented fallback
and its visual tradeoff. Do not quietly replace a sculptural 3D brief with flat cards.
Record chosen tools and exact installed versions in the delivered project's lockfile
and README. Do not label an unexercised route tested.

## Build the spectacle

Read [art direction](references/art-direction.md) and
[choreography](references/choreography.md). Before implementation, commit to a short
creative brief: title, world metaphor, dominant physical object, agent cast, palette,
type pairing, causal event sequence, target aspect ratios, and real/simulated data.
Use the user's supplied direction; make routine creative choices without a questionnaire.

1. Design the hero first: a mechanical oracle, enormous approval gate, miniature
   orbital factory, terrarium of researchers, speculative exchange, or another
   subject-specific machine. It should remain distinctive with all text covered.
2. Give agents separate silhouettes, roles, accent colors, motions, and concise
   status language. Do not merely arrange six identical glowing circles.
3. Connect visible consequences: intake → agent judgment → packet transport → hero
   reaction → updated instruments → receipt. Every layer shares one event model.
4. Add several scales of detail: giant spatial structure, medium workstations,
   miniature gauges, microtype, traces, labels, timestamps, and rewarding inspection.
5. Compose foreground cables, midground machinery, and background structure. Spend
   effects where they sell depth: selective glow, occlusion, contact shadows, trails,
   refraction, mist, and moving light. Preserve crisp readable text above the scene.
6. Implement useful controls: inspect an agent, select a scenario, pause, reset, and
   capture a reproducible frame. The controls must change the shared state.
7. Compose portrait deliberately for social media. A tall crop of the desktop is
   not a portrait design. Preserve the hero, the cause-and-effect sequence, and labels.

Default intensity is theatrical maximum. Increase topology, craftsmanship, lighting,
layered movement, unusual machinery, and narrative density—not full-screen flashing
or unreadable text. Support pause and reduced motion without making the still boring.

## Data and delivery

Real events must stay truthful. Simulations should be seeded and visibly labeled;
do not invent live agent actions, earnings, confidence claims, or external executions.
Use names and jokes in decorative copy without obscuring functional controls.
Keep decorative status separate from genuine connection/error status.

Run the [quality rubric](references/quality.md). Inspect actual rendered screenshots
at delivery sizes and several points in the animation; repair failures. Deliver the
working project, setup command, dependency lock, screenshot, tested controls, known
limitations, and video only if requested or part of the agreed deliverable. External
publication and tool access retain the user's authorization boundaries.
