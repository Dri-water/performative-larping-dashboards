# Contributing

Add a reproducible visual improvement, a platform recipe, or a tool recommendation
with a clear job. Avoid a catalog of interchangeable libraries.

For toolkit changes include: official documentation, capability, preferred route,
fallback and lost capability, license notes, date reviewed, and evidence level
(documented / example-tested / device-tested). Never call a route tested because its
README exists. Pin executable examples and commit lockfiles; keep recommendations
separate from the versions actually exercised.

For visual changes run the example build and verification. Inspect desktop and
portrait screenshots, not just the exit code. Include a paused frame and disclose
whether video export or physical-device behavior was tested. Preserve the seed and
shared simulation clock. Do not add credentials, copyrighted reference screenshots,
unlicensed models, or misleading live/P&L claims.

Keep the skill portable and its references inside its own directory. A new tool
must improve a specific outcome; it must not become mandatory for unrelated routes.
